# IIDXRecorder v0.6：日期目录与可读文件名版

已直接安装到 C:\IIDX。保留现有启动参数中的 -k IIDXRecorder.dll 即可。

## 现在怎么试

1. 启动游戏，保持现有 ASIO4ALL、TDJ 和全屏设置。
2. 登录后进入段位或 Arena，不需要找或点击「動画」。从第一曲开始录制，曲间保持原生编码器运行。
3. 完成整局，离开段位／Arena 总结果页后等待原生编码收尾；此时应保存一个包含各曲、曲间及总结果页的 MP4。匹配和第一曲开始前的选曲过程不在录制范围内。
4. 检查 C:\IIDX\recordings 中的 MP4。文件名为开始日期_模式_歌名或段位.mp4；Arena 或名称不可用时省略末项，同名追加 _2、_3 等。
5. 日志 C:\IIDX\IIDXRecorder.log 应依次出现 AUTO v0.5 installed、continuous scene hooks installed、AUTO SESSION BEGIN、AUTO SESSION END、AUTO FINAL SAVED。只有 installed 不等于实际录制成功。

验证版仍需真实游戏测试。如果崩溃、没有文件、无声、黑屏或长度不对，请保留上述日志与 Spice log.txt。Standard 和 VEFX＋EFFECT 跳关已由用户实测确认音视频正常。段位连续录制已由用户实机确认正常；Arena 仍待实机验收。v0.5 新增命名与日期目录，通过自动测试，实际歌名与段位名待下次游玩确认。

## 实现

针对当前 bm2dx.dll（PE 时间戳 0x69c347cc，SizeOfImage 0xBB3E000），只修改内存中两个 StageInit／重试位置的录制资格检查，并接管原生录制对象的初始化与收尾。另通过段位／Arena 的具体场景虚函数入口确定整局边界，整局期间保留主录制器的采集回调，不执行曲间暂停、停止和重置。离开总结果页时导出，模式退出或检测到模式变化时收尾。没有修改磁盘上的 bm2dx.dll，没有替换群文件中的游戏 DLL，没有改服务器地址和账号设置。

原生音视频编码和全屏取帧继续由游戏完成。先停止采集，再让游戏自己的编码器合并最终音视频，随后直接导出最终 MP4，不需要点击上传。自动模式不会修改原生中间文件的 MP4 封装，也不会把中间的独立轨道误当作最终录像。

此版本使用逆向确定的内部函数／对象布局。启用前核对 PE 版本、指令指纹和完整录制虚函数表；不匹配时不启用自动录制。更换游戏版本后不能直接保证兼容。

## 配置

IIDXRecorder.ini 与 DLL 同目录，修改后重启游戏。

[Recorder]
Enabled=1
GameModule=bm2dx.dll
OutputPath=recordings
DateFolders=0
FragmentedMP4=0
FlushIntervalMs=1000

[Native]
AutoRecord=1
FPS=0
Width=0
Height=0
AACBitrateKbps=0

- OutputPath：绝对路径或相对于 DLL 的路径，支持环境变量。默认 C:\IIDX\recordings。
- DateFolders：0 直接存入 OutputPath（默认），1 存入 OutputPath/2026-09-15 这样的日期文件夹。日期按录像开始的本地时间计算。
- AutoRecord=1：启用无按钮原生录制；0：退回旧的被动 MF 镜像模式。
- ContinuousCourses：1 启用段位／Arena 连续录制；0 退回 v0.3 的原生逐阶段保存行为。若新增连续逻辑影响游玩，可设为 0 后重启。场景入口校验失败也会退回逐阶段保存，并记录原因。
- FPS：0 保留游戏值，或 30／60／120。
- Width、Height：0 保留游戏值。自定义时需同时设置偶数宽高，范围 640–3840 与 360–2160。
- AACBitrateKbps：0 保留游戏值，或 64–320，步长 32。
- 帧率、分辨率、码率写入原生主录制对象的初始化参数，尚未完成真实游戏兼容性验证，首次测试请保持 0。声音来源是游戏内部，不是系统回录或麦克风。
- FragmentedMP4／FlushIntervalMs 仅用于 AutoRecord=0 的旧被动镜像模式。自动模式保持游戏原生格式，在正常收尾时导出，不承诺强退保护。

## 停用／回退

将 Enabled=0 后重启，或从启动参数中移除 IIDXRecorder.dll 即可停用。已有录像不会删除。旧版安装文件已在本次工作目录备份。

## 参考包

猫网包中的 010-record-api 是原生单曲录像的上传接收服务，不会独立连续录屏。它不能直接满足无按钮的自动启动和段位／Arena 整局录制。本次没有执行它，也没有应用它附带的 bm2dx.dll。

源码在 source 目录；build.ps1 可用 Zig 0.14.1 重编译。test_autoguard.cpp 验证版本保护和最终导出；test.cpp／validate.cpp 验证合成音视频。

## v0.5 文件命名

- 自动模式：2026-09-15_Standard_冥.mp4、2026-09-15_段位_SP九段.mp4、2026-09-15_Arena.mp4。
- 模式名使用 Standard、Step Up、PF、段位、Arena。未知模式保留数字标识。
- 歌名按原生数据库的 CP932 解码。段位由当前所选段位与 SP／DP 生成；Arena 不使用其中任何一曲的歌名。
- 开始录制时固定日期与名称；结果页切换歌曲或跨午夜不改变本段名称。
- 无法读取名称时省略末项；非法文件名字符改为下划线；名称最长 120 个 UTF-16 单元。
- 同名或已有同名 .partial 文件时使用 _2、_3 等序号；不会覆盖旧录像，也不会重命名已有录像。
- DateFolders 对旧被动路径也生效，但旧路径仍保留原来的文件名。
- INI 已逐项写明中文说明、可选值与默认值，并保存为 Windows 配置 API 支持的 UTF-16 LE。
- 测试通过：中日文名称、SP／DP 段位映射、根目录／日期目录、重复与 partial 占位、非法字符、Arena 省略、缺失信息安全降级；原有连续录制模拟回归通过。新增元数据读取位置已与当前游戏 DLL 核对。

## v0.6 文件名时间开关

在 [Recorder] 中设置 FilenameTime=0（默认）使用日期_模式_名称；设置 FilenameTime=1 使用日期_时-分-秒_模式_名称，例如 2026-09-15_00-23-05_段位_SP九段.mp4。时间取录制开始的本地时间。此项仅影响自动模式，不改变日期文件夹或防覆盖规则。修改后重启。
